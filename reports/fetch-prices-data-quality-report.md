| # | 問題 | 影響 | 嚴重度 |

### 步驟 3: 驗證獨立來源失敗

我嘗試用 TWSE OpenAPI ST92 和 TPEx OpenAPI 交叉驗證，但**兩個獨立來源都無法存取**（API 端點失敗或 IncompleteRead 錯誤）。所以 MIS API 仍是唯一可用且最可靠的來源。

## ✅ 改善措施 (已完成)

### 1️⃣ `fetch_prices.py` 加入守則

```python
def is_trading_day(now=None):
    """判斷是否為實際交易日 (避開週末)"""
    return now.weekday() < 5  # 週一至週五
```

**執行邏輯**:
- ✅ 週末直接擋住，不寫入 DB (`exit 0`)
- ✅ 盤中執行警告並擋住 (`exit 0`)，除非加 `--allow-intraday`
- ✅ 可用 `--skip-weekend-check` 強制執行

### 2️⃣ 建立專屬 cron job

| Cron | 時間 | 動作 |
|------|------|------|
| `4684290d7ace` | 每日 13:35 (平日) | 抓取收盤價並寫入 DB |

**為什麼是 13:35？**
- 13:30 台股收盤
- 13:35 MIS API 已有「真實成交價」
- 之後 13:36-13:50 才有「best_bid_estimate 警告」會消失

### 3️⃣ 加入重試機制 (fetch_with_retry)

```python
def fetch_with_retry(pairs, max_retries=3, delay_sec=5):
    """帶重試的抓取，解決 MIS API 不穩的問題"""
    for attempt in range(max_retries):
        try:
            result = fetch_quote(pairs)
            if result:
                return result
            time.sleep(delay_sec)
        except Exception as e:
            print(f"   ⚠️ 第 {attempt+1} 次抓取例外: {e}")
            ...
```

## 🎯 Quinn 的承諾

1. **未來抓的每一筆收盤價**都會經過週末/盤中檢查
2. **每日 13:35 自動抓取**，不再手動分散
3. **MIS API 不穩時自動重試** 3 次
4. **若仍然失敗**，誠實回報「抓取失敗」而不是用 best_bid_estimate 假裝成功

## ⚠️ 已知的限制

| 限制 | 原因 | 影響 |
|------|------|------|
| 無法處理**國定假日** | 需要手動暫停 cron | 國定假日會寫入 MIS 最後資料 |
| MIS API 是**唯一來源** | TWSE OpenAPI 失效 | 無法跨來源驗證 |
| **延遲 15 秒** | 13:30 收盤後 5 分鐘 | 若有當沖或最後一盤大單，可能略低 |

**建議老大**：
- 遇到國定假日 (例如 10/10 雙十) 前一晚，手動 `hermes cron pause 4684290d7ace`
- 重要決策**不要只依賴 DB 收盤價**，可手動到券商終端機確認
